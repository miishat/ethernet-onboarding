## Intended scope and API

The reserved profile ID is `400gbase-dr4-tx-v1`. The selected target edition is **IEEE Std 802.3-2022**, without assuming later amendments. Its normative text must be checked before the profile is enabled. Metadata describes the intended 16 PCS lanes, four physical lanes and 53.125 GBd geometry. These values are candidate metadata, not an implemented mapping. The draft sources below provide context for 16 lanes and 53.125 GBd, but do not establish the selected edition's algorithms.

`types.ts` supplies the interfaces in Task 2. `PROFILE`, `PROFILE_VERIFICATION`, `DEFAULT_FRAME`, and `DEFAULT_STREAM` are frozen. Consumers should copy a default into editable state and call `getProfileSupport(rate, dir, gen)` before constructing any complete run. The separate verification state does not change the agreed `Profile` interface. Rejections explain an unsupported rate, direction or lane generation before reporting the verification block for the intended tuple.

`DataRef` uses a zero-based half-open interval `[start, start + count)` in its buffer's units. A buffer ID is resolved within its stage. Octet and bit buffers use `Uint8Array`; RS-symbol buffers can use `Uint16Array`. A bit buffer has one bit per element, not packed octets. `MacFrame.bytes` denotes destination through FCS; `withoutFcs` omits FCS and neither buffer includes preamble, SFD or idles. These are application representation decisions, not substitute serialization rules. A later implementation must not label a partial run as the complete named profile.

## Teaching defaults and bounded execution

The frozen draft contains destination `02:00:00:00:00:02`, source `02:00:00:00:00:01`, EtherType text `88B5`, and the 64 payload octets `00` through `3F`, ascending. Hex text represents octets in display order and is not a bit-serialization rule. The payload is a local experimental teaching sequence with no IP, TCP or other higher-layer interpretation. This is the requested local example; this task does not establish EtherType allocation rules.

The requested initialization is `scramblerSeedHex = 3FFFFFFFFFFFFFF` (58 one bits), `markerPrbsSeed = 0x1ff`, `markerBlockPhase = 0`, `lanePhase = 0`, and `prefixIdleOctets = 4096`. These values preserve the requested state while verification is blocked. They are not asserted to be a valid hardware reset state. Acceptance by the scrambler and marker PRBS recurrences is still unverified.

The proposed phase convention is: marker phase zero is absolute transcoded 257-bit block index `0`, at the boundary immediately before an alignment-marker group reservation. `absoluteStreamBlock` counts contiguous pre-insertion transcoded 257-bit block positions from that boundary and is carried across chunks and windows. Lane phase zero names the first distribution unit assigned to logical lane zero at the same boundary. The research identifies a candidate 40-block, two-codeword boundary, but a final IEEE line check is still required before phase fields drive computation. A `RateMatchPolicy` is also required: IEEE does not prescribe where an implementation removes individual eligible Idles to make AM capacity. In particular, zero phase does not imply that 4096 prefix idles can simply be added after a marker.

After verification, a run must add Idles according to its selected `RateMatchPolicy` until it finishes the final FEC codeword pair and lane-distribution group without truncating the requested frame. `MAX_CODED_BITS = 262144` is an application limit on total coded output across lanes, including prefix, markers, frame, parity and trailing completion. A future run builder must calculate the required size and reject an over-cap request with a `run` error before allocating output; it must never truncate a frame. There is no run builder yet, so this task does not claim that cap enforcement is implemented. Later marker boundaries require a phase-controlled window with carried state and recorded deletions, not storing a full marker period or resetting state at the window boundary.

## Standalone RS primitive

The frozen nonzero fixture is generated by `scripts/rs544-reference.py`, which uses independent shift-and-reduce multiplication and polynomial long division. Its source revision and SHA-256, plus the canonical message/codeword artifact SHA-256, are recorded in `test/fixtures/inspector/manifest.json` and in the fixture itself.

This primitive does not accept Ethernet bits or claim a `400gbase-dr4-tx-v1` result. The candidate Ethernet adapters below remain disabled until their final IEEE line check and fixture admission succeed.

### PMA mapping contract

`PmaMappingProfile` describes one observable PMA/module implementation. It must include provenance and fixture hash; exact scope/boundary; 16:4 geometry; and one schedule per PMD lane with `unit: 'bit'`, `periodBits`, `sourcePcsLaneByPhase`, `initialPhase`, and the deterministic phase rule `phase = (initialPhase + absoluteOutputBit) mod periodBits`. The source-lane schedule length must equal `periodBits`, and `absoluteOutputBit` must carry across chunks and windows. The remaining required fields are boundary bit indexing; PMD-to-MDI and MDI-to-fiber maps; polarity transform and stage; dibit order/significance; full dibit-to-label-and-normalized-level map; precoder mode/state/reset; and the PMA training/PCS-scrambler boundary. An illustrative mapping must carry an illustrative profile ID and cannot enable this profile.

### Rate-match ledger contract

`RateMatchPolicy` must be a deterministic, serializable policy, not a record of its result. It identifies eligible Idle encodings; an ordered candidate rule and tie-breaker; maximum deferral; and a frame-boundary rule. Its AM schedule uses `unit: 'transcoded-257b-block'`, `cadenceBlocks`, `reservationBlocks`, `fecPairBlocks`, and `phaseZeroAbsoluteStreamBlock: 0`. The target profile must not fill the numeric cadence or reservation capacity until the final IEEE line check verifies them. For an input at absolute block `b`, the next reservation is `r = phaseZeroAbsoluteStreamBlock + max(0, ceil((b - phaseZeroAbsoluteStreamBlock) / cadenceBlocks)) * cadenceBlocks`; its group index is `(r - phaseZeroAbsoluteStreamBlock) / cadenceBlocks`, and `r` must satisfy the declared FEC-pair boundary rule. The policy must also state the required deletion capacity for that reservation and deterministically select the ordered eligible input Idles that satisfy it. Thus the input words, their absolute stream origin, policy and initial AM state reproduce the same deletion ledger without relying on a prior displayed window.

Each decision produces a `RateMatchDeletion` entry containing the original word, octet and bit position; the exact Idle octets and control mask; the selected policy ID; a reason of `alignment-marker-reservation` or `trailing-fec-completion`; and marker-reservation context: group index, insertion-bit offset, FEC-pair index and boundary kind. `PreparedStream`, `MarkerPlan` and `MarkerResult` each carry the immutable ledger. A removed-Idle count may be displayed only as a derived value, so a later window cannot lose the deletion provenance needed to reproduce the stream.

## Fixture policy and unblock procedure

`test/fixtures/inspector/manifest.json` distinguishes **candidate sources** from accepted fixtures. The accepted `fixtures` array is empty. Candidate hashes cover the exact downloaded HTTP response bytes, including labels and line endings, not interpreted protocol bits. Hashes establish source integrity only. Candidate `inputState` records the relevant published labels and explicitly unresolved conventions; it does not pretend the teaching seed generated those examples. No tests fetch the network or regenerate expected outputs.

To unblock this task, complete the IEEE Reading Room or licensed-copy final line check, resolve each final-profile rule with exact clause/table/page citations, select the implementation-owned `RateMatchPolicy` and any `PmaMappingProfile`, and admit independently verified fixtures. For an independently implemented Python reference, record its source/revision and reviewer, all input bytes and initial state, the precise serialization convention, complete rate-match ledger, PMA absolute-phase state, output artifact hash and stage-specific verification scope. Keep it independent of production TypeScript, commit the reviewed expected outputs once, and compare against those stored outputs during tests. Include mixed start/terminate blocks, marker boundaries, nontrivial RS parity, the full two-codeword lane permutation, and selected lane/PAM4 ordering, rather than relying on round trips or all-zero examples.

Until every requirement above passes, `getProfileSupport` returns `supported: false` for every tuple, including the intended tuple. Only then may the intended tuple's capability test change to `supported: true`; RX, 800G, 1.6T and other lane generations remain unsupported.
